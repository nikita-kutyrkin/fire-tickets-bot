## ✨ Возможности

- 🔥 **Только реально выгодные билеты.** Бот сравнивает цену с обычной для маршрута, а не просто ищет самое дешёвое.
- 🛫 **Свои города.** Несколько городов вылета и направлений, или все направления сразу.
- 💸 **Гибкие фильтры.** Минимальная скидка, потолок цены, сколько дней вперёд смотреть.
- 📆 **Поездка.** Одновременно с ближайшими днями можно следить за конкретными датами, например домой на новогодние каникулы (`28.12-08.01`), и получить билет, когда он заметно подешевеет. В уведомлениях билеты на поездку идут отдельным разделом. Ближайшие дни можно выключить, если нужна только поездка.
- 🔔 **Уведомления сами приходят.** Бот регулярно проверяет цены и не присылает один билет дважды: повторно, только если он подешевел ещё хотя бы на 10%.
- ⚙️ **Настройки кнопками.** У каждого пользователя свои, всё меняется в `/settings`.

## 🧠 Как бот понимает, что билет горящий

1. Для каждого маршрута бот считает **обычную цену**: медиану самых дешёвых билетов по дням на 30 дней вперёд. Для билетов на поездку медиана считается по датам поездки и неделе до и после них: новогодние билеты сравниваются с новогодними ценами, а не с октябрьскими. Значение кешируется на сутки.
2. Билет **горящий**, если он дешевле обычной цены хотя бы на `MIN_DISCOUNT_PERCENT` процентов (по умолчанию 40%) и стоит не больше `MAX_PRICE` (если он задан).
3. Если по маршруту мало данных и обычную цену посчитать нельзя, бот присылает все билеты дешевле `MAX_PRICE`.

Цены берутся из [Travelpayouts Data API](https://support.travelpayouts.com/hc/ru/articles/203956163): это кэш поисков Aviasales примерно за последние 48 часов.

## 📈 Нагрузка

У API нет суточного лимита, только 600 запросов в минуту на каждый метод. Бот держится ниже (540 в минуту), одинаковые запросы 10 минут берёт из памяти и склеивает одновременные в один, а при превышении лимита ждёт и повторяет запрос.

Нагрузочный тест на поддельном API (700 пользователей из 25 городов, 40% следят за всеми направлениями):

| Сценарий | Результат |
|---|---|
| Фоновая проверка всех 700 пользователей | ~5 мин (интервал 20 мин), ~2 200 запросов, пик 513 в минуту |
| Повторная фоновая проверка | ~1,5 мин, ~180 запросов |
| 70 человек одновременно жмут «Проверить» | медиана 7 с; 18–25 с, если совпало с фоновой проверкой или ботом только что перезапущен |

## 💬 Команды

| Команда | Что делает |
|---|---|
| `/start` | подписаться на уведомления и открыть главное меню: проверка билетов, города, настройки |
| `/settings` | настройки кнопками: скидка и потолок цены (даты выбираются на главном экране) |
| `/from Москва` | добавить город вылета (можно несколько через запятую) |
| `/to Волгоград` | следить только за нужными направлениями (можно несколько через запятую). Без городов бот смотрит все направления |
| `/check` | найти горящие билеты прямо сейчас. Если горящих нет, а направления выбраны, покажет самые дешёвые билеты по ним |
| `/stop` | выключить уведомления (настройки сохраняются). То же делает кнопка «🔕 Выключить уведомления» на главном экране, включить обратно — «🔔 Включить уведомления» |

Бот опрашивает API так, чтобы покрыть всех пользователей сразу и не запрашивать один маршрут повторно.

Остановить: `Ctrl+C`.

При запуске бот сам выставляет в Telegram список команд, описание и короткое описание профиля. Аватарку ставят вручную: в [@BotFather](https://t.me/BotFather) отправьте `/setuserpic`, выберите бота и пришлите [assets/logo.png](assets/logo.png).

## 🔑 Как получить токен Travelpayouts

1. Зарегистрируйтесь на https://www.travelpayouts.com/ (бесплатно, можно как физлицо).
2. В личном кабинете откройте **Программы**, найдите **Aviasales** и нажмите **Подключить**. Когда попросят указать площадку, дайте ссылку на бота, например `https://t.me/fire_tickets_bot`.
3. Откройте **Профиль** (иконка справа вверху), вкладку **API-токен** (или раздел «Инструменты → API»).
4. Там будут:
   - **API-токен**, строка из 32 символов. Запишите её в `.env` в `TRAVELPAYOUTS_TOKEN`.
   - **Маркер партнёра**, число вроде `123456`. Запишите его в `.env` в `TRAVELPAYOUTS_MARKER`. Маркер добавляется к ссылкам, и с покупок по ним вам начисляется комиссия.

## ☁️ Деплой на bothost.ru

Бот запускается файлом `main.py` в корне, bothost находит его автоматически. Платформа собирает Docker-образ с Python 3.11, ставит зависимости из `requirements.txt` и задаёт `DATA_DIR=/app/data`. Там лежат база и кэш справочников, и эта папка переживает обновления кода.

1. Код должен лежать в репозитории на GitHub. Файлы `.env` и `data/` в репозиторий не попадают (см. `.gitignore`).
2. На https://bothost.ru/create-bot.php выберите платформу **Telegram**, библиотеку **aiogram**, укажите токен бота, ссылку на репозиторий и ветку `main`. Главный файл можно не указывать (или указать `main.py`).
3. В **«Переменные окружения»** бота добавьте `TRAVELPAYOUTS_TOKEN` и по желанию `TRAVELPAYOUTS_MARKER`, `ORIGIN`, `MIN_DISCOUNT_PERCENT`, `MAX_PRICE`, `DAYS_AHEAD`, `CHECK_INTERVAL_MINUTES`, `TIMEZONE`. `BOT_TOKEN` платформа задаёт сама из токена, указанного при создании.
   Если переменные окружения недоступны на тарифе, загрузите файл `.env` в папку `data` через файловый менеджер панели, и бот прочитает его оттуда.
4. В **«Логах работы»** должны появиться строки `База данных: /app/data/bot.db` и `Start polling`.

> [!WARNING]
> Один токен работает только в одном запущенном боте. Если бот работает и на компьютере, и на сервере, Telegram выдаёт ошибку `Conflict`. Остановите локальную копию.

Обновление: `git push` в ветку `main` (на платных тарифах бот обновится сам) или кнопка **«Обновить из Git»** в панели.

## ⚙️ Настройки (`.env`)

| Переменная | Что значит |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `TRAVELPAYOUTS_TOKEN` | токен API Travelpayouts |
| `TRAVELPAYOUTS_MARKER` | партнёрский маркер (необязательно) |
| `CHECK_INTERVAL_MINUTES` | как часто проверять цены |
| `TIMEZONE` | часовой пояс для «сегодня» и «завтра» (по умолчанию `Europe/Moscow`) |

Значения по умолчанию для **новых** пользователей (дальше каждый меняет свои в `/settings`):

| Переменная | Что значит |
|---|---|
| `ORIGIN` | IATA-код города вылета: `LED` — СПб, `MOW` — Москва, `KZN` — Казань, `SVX` — Екатеринбург |
| `MIN_DISCOUNT_PERCENT` | минимальная скидка от обычной цены маршрута, % |
| `MAX_PRICE` | потолок цены, ₽ (`0` — без потолка) |
| `DAYS_AHEAD` | `0` — только сегодня, `1` — сегодня и завтра и т.д. |
